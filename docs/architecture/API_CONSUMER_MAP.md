# API consumer map: first reliability stage

Source inventory at baseline `6e138e2cb5a095c4cc0a856291430cf6a3b683fb`, updated for this branch. Paths below are logical endpoint paths under configured upstream URLs. This is source/fixture evidence; live provider contracts and deduplication behaviour were not verified. No endpoint is approved for deletion.

| Entrypoint/workflow | Client operation and method/path | Identity/authentication and contract evidence | Timeout/retry and stage status |
| --- | --- | --- | --- |
| Search, browsing, play, queue pagination, feedback continuation | `HearApiClient.search`: POST `/alexa/search` | Endpoint prefix mapping remains client-owned; caller payloads currently supply listener/Alexa IDs. `search-request.schema.json`, `search-response.schema.json`, `test_api_client.py`, `test_search_queue.py`. | Existing bounded per-call timeout and configured 5xx retries preserved. Pool binding fixed; typed inputs, identity binding and total retry budget remain open. |
| Source/location availability and publication/track choice | `HearApiClient.availability`: POST `/alexa/availability` | Canonical or supported Alexa identity in caller payload; API key on bound pool. `availability-request.schema.json`, `test_api_client.py`, `test_availability_flow.py`. | Existing retry policy preserved; filter consolidation and full response validation remain open. |
| Bootstrap canonical identity | `HearApiClient.resolve_listener_identity`: POST `/alexa/listeners/resolve` | `ListenerIdentityService` / identity middleware; allowlisted identity payload. `listener-identity-resolve.schema.json`, `test_identity.py`. | Existing bootstrap timeout/cache preserved. Do not require a canonical ID before this operation. |
| Listener launch/profile sync | `HearApiClient.sync_listener`: POST `/alexa/listeners/sync` | `ListenerSyncService`; `ListenerPayload.registration` allowlist. `listener-sync.schema.json`, `test_api_client.py`. | No new write retries. Contract/consumer verification required before consolidation. |
| Listener registration and permissions | `HearApiClient.register_listener`: POST `/alexa/listeners/register` | Onboarding/permission callers; explicit registration allowlist. `test_api_client.py`, `test_permission_flow.py`, `test_onboarding_completion.py`. | No new write retries. Preserved as a separate operation. |
| Resolver workflow, CanFulfill, diagnostic | `ResolverClient.resolve` / `resolve_utterance`: POST `/resolve` | API key; optional Alexa/canonical identity; UK timezone/country. `resolver-request.schema.json`, `resolver-response.schema.json`, `test_resolver_client.py`. | Fixed pool binding and conservative anonymous caching. Anonymous diagnostic preserved. Listener-bound constructor migration remains open. |
| Spoken notification inbox and proactive notification worker | `NotificationApiClient.pending` / `update`: POST `/alexa/notification` | Canonical listener only; operation/purpose/status fields preserved. `notification-item.schema.json`, `notification-delivery-message.schema.json`, `test_notifications.py`. | Bound upstream/authentication; worker batch deadline; unsuccessful required status writes remain retryable/redrivable. Backend inbox remains authoritative. |
| Playback, feedback, social and report producers | `SqsEventClient.send`: SQS `SendMessage` | Existing queue URL/IAM role; stable v3 envelope schema fields. `backend-event.schema.json`, `test_outbound_events.py`. | Producer/state transaction remains open. Current follow/report occurrence ID semantics have not changed. |
| Outbound event Lambda | `WebhookEventClient.send`: POST configured `WEBHOOK_OUTBOUND_URL` | Existing API-key and HMAC headers. Complete incoming envelope validation at consumer; original accepted envelope forwarded unchanged. `backend-event.schema.json`, `test_outbound_events.py`, `test_reliability_foundation.py`. | Remaining batch deadline passed from Lambda; failures use existing standard SQS redrive and partial failure response. Backend deduplication unverified. |
| Proactive notification delivery | `ProactiveEventsClient`: LWA token then POST Alexa proactive endpoint | Application credentials and per-item unicast target remain separate. `test_notifications.py`. | Existing permanent/transient delivery classification preserved; unsuccessful backend acknowledgement now remains in retry/redrive flow. No exactly-once claim. |
| Alexa locality/profile | `AlexaSettingsClient.get_device_address` / `get_profile_setting`: GET approved Alexa device/profile paths | Per-request platform endpoint, permission and access token; `test_alexa_device_address.py`, `test_identity.py`. | Existing endpoint validation and timeout preserved. More explicit constructor lifetimes remain open. |
| Progressive speech | `ProgressiveResponseClient.send`: POST Alexa directive service | Per-request Alexa endpoint/token/request ID; `test_cards_and_progressive.py`. | Existing best-effort behaviour preserved. Offline unit transport prevents real calls from fixture tokens. |

Worker and diagnostic entrypoints were included in this inventory. The implementation removes no API consumers and introduces no new external endpoint.

Platform response restrictions were checked against [Amazon's AudioPlayer reference](https://developer.amazon.com/en-US/docs/alexa/custom-skills/audioplayer-interface-reference.html). SQS handling follows [AWS partial-batch failure guidance](https://docs.aws.amazon.com/lambda/latest/dg/services-sqs-errorhandling.html).
